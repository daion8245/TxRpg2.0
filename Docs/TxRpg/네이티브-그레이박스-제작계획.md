# TxRPG 퍼즐·전투 그레이박스 제작 계획

2026-11-24 · Unity 6000.3.28f1 · 기존 TxRpg2.0 프로젝트

## 플레이 경로

`Village_01`에서 기존 기사를 조작한다. 방패를 알고 시작해 발사를 획득하고, 단어를 선택해 투척 방패를 만든다. 방패가 충격판에 닿으면 문이 열린다. 통과하면 Unity가 `BattleTest`를 로드한다. 마을에서 배운 단어로 덱을 편성하고 적 1~3마리의 예지를 읽어 다섯 칸을 계획한다. 결과에서 재도전하거나 마을로 돌아온다. 고정 손패의 A/B 비교는 전투 씬에서도 바로 실행할 수 있다.

## 1. 마을 퍼즐

| 재사용할 자산 | 에디터에서 편집할 항목 | 동작 판정 |
| --- | --- | --- |
| 실제 `Assets/Scenes/Village/Village_01.unity`의 Player, Animator, VillagePlayerMovement, PlayerInput | 기존 이동·점프와 지면 레이어, 카메라 구도, 이동 가능한 발판 높이 | 룬에 접근하고 획득한 뒤 양방향으로 돌아갈 수 있다. |
| 기존 마을 배경, Grid/Tilemap, 조명, EventSystem | 새 룬·충격판·문은 Hierarchy에서 개별 선택 가능한 오브젝트다. SpriteRenderer, Collider2D, 출구 트리거를 배치한다. | 제자리 방패와 빗나간 투사는 문을 열지 않는다. 실제 투척 방패 충돌 시 한 번만 열린다. |
| 기존 한글 TMP 폰트와 Unity UI | CanvasScaler, 버튼, 주문 초안·비용·사유 TMP, 발사체 프리팹과 효과음의 Inspector 참조 | 버튼으로 단어를 묶고 풀고 시전할 수 있다. UI는 플레이 전에도 씬에서 보인다. |

단어·문 상태와 인카운터 설정만 두 씬 사이에서 전달한다. 마을 재시작은 초기 상태, 전투 후 복귀는 열린 문과 습득 상태를 사용한다. 설정 메뉴·타일맵·애니메이터 등 기존 콘텐츠의 직렬화 참조를 보존한다.

## 제작과 인수

기능 단위로 Claude Code Haiku 5.5 Max가 제작한다. 실제 씬과 프리팹을 저장한 뒤 Gemini Neon High와 Claude Opus xhigh가 차례로 검토한다. 이 세션이 각 보고서와 Unity 실행 증거를 대조해 승인하거나 수정을 지시한다. 변경 전 단일 씬 실험 결과는 새 씬의 인수 근거에서 제외한다.

최종 검사는 실제 두 씬의 씬 GUID, 직렬화된 버튼·TMP와 참조, 플레이어 이동·충돌, 양방향 씬 전환, 덱 및 1~3마리 전투, 고정 결과, Windows 실행본을 대상으로 한다. 최종 런타임에서 IMGUI 화면, 수제 물리 시뮬레이터, 매 실행 시 씬·UI를 만드는 생성기를 제거한다. 일회성 에디터 저작 도구는 작업 복사본에서만 사용한다.
